# 오늘 뭐 보지? — 디자인 담당 가이드

이 문서는 `seoul-rag-demo`의 화면을 설계하거나 수정할 때 사용하는 기준입니다. 구현 현황은 `app/page.tsx`와 `app/globals.css`, 기능 범위는 `README.md`를 확인하세요.

## 목표와 핵심 경험

사용자는 **질문을 입력하고 → 실제 서울 문화행사를 찾고 → AI 요약의 근거와 공식 원문을 확인**할 수 있어야 합니다. 이 앱은 강의 중 RAG 흐름을 보여주는 데모이므로, 첫 화면과 2분 시연에서 이 경로가 바로 보이게 설계합니다. 로그인이나 배포 과정을 핵심 화면으로 만들 필요는 없습니다.

디자인의 우선순위는 다음과 같습니다.

1. 검색어·지역·무료 조건과 검색 버튼을 쉽게 찾는다.
2. AI 답변과 공공데이터 검색 결과를 시각적으로 구별한다.
3. AI가 인용한 번호를 행사 카드 및 공식 원문 링크와 쉽게 대조한다.
4. 자료가 없거나 AI 연결이 실패해도 사용자가 현재 상태와 다음 행동을 이해한다.

## 화면 구조

```text
헤더: 서비스 이름 / 강의 데모 표시
소개: 무엇을 찾을 수 있는지 한 문장
연결 상태: 서울 API / AI 사용 가능 여부
작업 영역
  왼쪽: 질문 → 예시 질문 → 지역·무료·지난 행사 조건 → 검색
  오른쪽: 상태 안내 → AI 요약(있을 때) → 행사 카드 → 조회 정보
푸터: 데이터 제공처 / 원문 확인 안내
```

데스크톱에서는 질문과 결과를 나란히, 모바일에서는 질문 다음에 결과가 이어지도록 배치합니다. AI 요약은 행사 카드보다 앞에 두되, 요약만 보고 판단하지 않도록 참조 번호와 원문 확인 링크를 분명히 보여줍니다.

## 반드시 설계할 상태

| 상태 | 화면에서 보여줄 것 | 사용자가 할 수 있는 일 |
| --- | --- | --- |
| 첫 방문 | 예시 질문 `무료 전시`, 입력 방법, 아직 결과가 없다는 안내 | 질문을 수정하고 검색 |
| 서울 API 키 없음 | 연결 준비 전 안내 | 키 설정 후 서버 재시작 |
| Gemini 키 없음 | 검색은 가능하고 AI 요약은 없다는 표시 | 행사 카드와 원문 확인 |
| 검색 중 | 진행 상태와 버튼 비활성화 | 응답 대기 |
| AI 답변 성공 | AI 요약, 참조 번호, 해당 행사 카드, 공식 원문 링크 | 근거와 원문 대조 |
| AI 답변 실패 | 검색 결과는 유지하고 AI 요약 실패를 설명 | 원문 확인 또는 다시 검색 |
| 검색 결과 0건 | 근거가 없음을 명시 | 검색어·지역·무료 조건 변경 |
| 데이터 연결 오류 | 오류를 간결하게 설명 | 다시 시도 |

검색 결과 0건일 때 AI 답변을 꾸며 내는 화면을 설계하지 않습니다. 행사 날짜·요금·예약 여부가 자료에 없으면 `원문 확인`으로 표시합니다. `AI 연결 준비`는 키가 설정됐다는 뜻이며, 실제 답변 성공과는 구별합니다.

## 현재 시각 기준

현재 구현의 방향은 **차분한 문화 잡지 + 검증 가능한 데이터 서비스**입니다. 전체 화면을 새로 설계할 때도 검색과 출처의 가독성을 먼저 지킵니다.

| 항목 | 현재 값·규칙 |
| --- | --- |
| 배경 | 크림 `#f4f3ec` |
| 본문 글자 | 짙은 녹색 `#253a2e` |
| 보조 글자 | 회녹색 `#657067` |
| 경계선 | 연녹회색 `#d4d9cc` |
| 주요 버튼 | 녹색 `#294c39` |
| 강조 | 주황 `#c14d31` |
| 글꼴 | 제목은 명조 계열, 본문·입력은 고딕 계열 |
| 데스크톱 폭 | 콘텐츠 최대 `1248px`, 질문 영역 `350px` |
| 모바일 전환 | `760px` 이하에서 한 열 배치 |

색상만으로 상태를 전달하지 말고 `AI 답변 + 검색 근거`, `검색 근거`, `연결 확인 필요` 같은 문구를 함께 둡니다. 장식 그림은 내용을 가리지 않아야 하며, 모바일에서는 생략할 수 있습니다.

## 상호작용과 문구

- 검색 버튼은 질문 입력 이후 가장 눈에 띄는 행동이어야 합니다. 예시 질문 버튼은 값을 채우고, 검색은 사용자가 직접 실행합니다.
- 무료 체크박스와 지역 선택의 현재 값을 분명히 표시합니다. 지난 행사는 기본적으로 제외합니다.
- 결과 카드는 제목, 지역·분류, 기간, 장소, 요금, 대상, **행사 원문 확인** 순서로 읽히게 합니다.
- AI 요약의 참조 번호를 누르면 대응하는 행사 카드로 이동합니다. 공식 원문 링크는 카드에서 열립니다.
- 긴 행사 제목, 긴 장소명, 여러 줄의 AI 답변이 들어와도 내용이 잘리거나 겹치지 않아야 합니다.
- `이번 주말` 같은 표현은 날짜를 자동 계산해 필터링하지 않으므로, 화면에서 제공하지 않는 기능처럼 보이게 쓰지 않습니다.

## 접근성과 화면 크기

- 입력 필드에 보이는 라벨을 유지하고, 키보드만으로 검색·필터·출처 링크에 접근할 수 있게 합니다.
- 포커스 표시를 유지합니다. 현재 구현은 주황색 외곽선을 사용합니다.
- 모바일 너비 `390px`와 데스크톱 `1440px`에서 검색 입력부터 공식 원문 링크까지 확인합니다.
- 로딩·오류·0건·성공 상태를 글자로도 알립니다. 작은 화면에서 가로 스크롤이나 버튼 잘림이 없어야 합니다.

## 디자인 담당자의 산출물

1. 데스크톱·모바일 화면과 위 상태별 시안. 모든 상태를 별도 전체 화면으로 그릴 필요는 없지만 차이가 보이는 컴포넌트 변형은 제공합니다.
2. 색상·글꼴·간격·버튼·입력·카드·상태 메시지의 공통 규칙.
3. 검색 버튼, 예시 질문, 필터, 참조 번호, 원문 링크의 동작 메모.
4. 개발자가 바로 적용할 수 있는 컴포넌트 이름과 상태별 문구. API 필드나 결과 의미를 바꾸는 제안은 개발 담당자와 함께 확인합니다.

완료 기준은 `무료 전시` 검색에서 **질문 → AI 요약 → 인용 행사 → 공식 원문** 경로가 한눈에 보이고, AI가 실패해도 사용자가 공공데이터 결과를 계속 확인할 수 있는 것입니다.
