SETUP · STEP 1 · 터미널 설치

복사 한 줄 — 자기 OS만

MAC — ⌘+Space → "터미널" → Enter
$ curl -fsSL https://claude.ai/install.sh | bash
WINDOWS — 시작 → "PowerShell" → Enter
> irm https://claude.ai/install.ps1 | iex
공통 · 건너뛰면 안 되는 한 가지: 설치가 끝나면 터미널을 완전히 종료(⌘Q)했다가 다시 열기 — 재시작해야 claude 명령을 찾는다.

Node.js 등 사전 설치 불필요 · Windows에서 git 안내가 나오면 git-scm.com 설치(전부 Next) 후 PowerShell 재시작

준비된 3개를 하나씩 완성한다

기능마다 완료 기준 3문장

  • 입력: 사용자가 무엇을 누르고 입력하는가
  • 결과: 화면에 무엇이 보여야 성공인가
  • 유지: 새로고침·재실행 뒤에도 남아야 하는가

팀 공통 작업 원칙

  • 세 기능을 한 번에 요청하지 않는다
  • 기능 하나 끝날 때마다 직접 눌러본다
  • 완료되면 커밋 + /clear
  • 막히면 기능 추가 대신 범위를 줄인다
  • 잘하는 팀도 네 번째 기능은 금지
오늘은 다시 기획하지 않는다. 준비한 핵심기능 3가지를 작동하는 상태로 완성하는 것이 목표다.

APPENDIX · 명세 공식

좋은 요청 = 맥락 + 목표 + 제약 + 완료기준

  • 맥락 — 어느 화면·어떤 상태에서"메인 페이지의 요청 목록에서"
  • 목표 — 무엇이 되어야 하는가입력과 기대 출력
  • 제약 — 건드리지 말 것·지킬 것"다른 기능은 그대로 둬"
  • 완료 기준 — 내가 눌러 확인할 문장검증 단계와 맞물리는 톱니
EXAMPLE
[맥락] 메인 페이지에 산책 요청 목록이 있어.
[목표] 상단에 "요청 등록" 폼 추가 — 날짜·시간대·메모 입력, 저장하면 목록 맨 위에 바로 표시.
[제약] localStorage 사용, 기존 목록 디자인 유지.
[완료기준] 등록 → 목록 반영 → 새로고침해도 유지.

팀이 실패하는 방식 5가지

  • 로그인·결제·관리자부터 만들기 — 점수 없는 곳에 반나절을 붓는다
  • 검증 안 된 새 기술 도입 — 검증은 행사 전에 — 해커톤에선 익숙하고 검증된 스택만
  • 새벽 3시의 "전체 구조 정리" — 피곤할수록 대규모 구조 변경 금지
  • API 키를 코드에 하드코딩한 채 공개 — 키 유출 사고 · .env와 .gitignore로
  • 발표 준비 0분 — 기능 100% × 전달 0% = 0점

이 다섯만 피하면 — 중간 이상은 보장된다.

환경변수 등록 → main을 Production으로

# DB 스키마도 코드처럼 버전 관리
$ supabase migration new create_core_tables
$ supabase db reset # 로컬 재현·검증
$ git add supabase/migrations && git commit
$ supabase link
$ supabase db push # 운영 DB 반영
  • Production 환경변수 등록 후 재배포
  • main만 운영 도메인에 연결
  • 도메인 추가 → A/CNAME 설정
  • SSL·로그·권한·CRUD 최종 확인
운영 원칙: 코드 배포와 DB 배포는 별개다. DB migration 먼저 → 앱 배포 다음. 운영 DB를 대시보드에서 즉흥 수정하지 않는다.
