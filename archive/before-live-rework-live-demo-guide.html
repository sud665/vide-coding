강사 메모
완성된 결과를 먼저 보여준 뒤 기능 하나를 추가합니다. 현재 프로젝트는 Next.js가 아니라 HTML/CSS/JavaScript와 Node.js로 구성되어 있다고 명확하게 설명하세요.

PRE-FLIGHT · 강의 시작 전

라이브는 준비된 환경에서 시작합니다.

오늘 미리 준비

  • 완성본을 보관하고 별도 시연용 사본 만들기
  • 시연본에서 자치구 선택 UI와 지역 필터 제거
  • 무료 검색·원문 링크가 동작하는지 확인
  • Vercel 데모 프로젝트와 환경변수 사전 설정
  • 완성본 동작 영상 1~2분 녹화

시작 명령어

cd seoul-rag-demo
npm run dev
로컬 데모 열기 ↗

Node.js 20.19 이상 필요. 시연본과 완성본을 동시에 실행할 때는 서로 다른 PORT를 사용하세요.

현재 프로젝트는 완성본입니다. 지역 필터를 제거한 시연본은 별도로 준비해야 합니다. 화면 공유 중 .env.local을 열지 마세요.
강사 메모
준비 슬라이드는 강의 전 체크용입니다. 시연본의 기존 지역 필터 테스트도 기준 상태에 맞게 정리해 두세요. API 키는 코드·프롬프트·터미널 출력에 표시하지 않습니다.

02 · 03:00–07:00

수정 전에, AI가 구조를 읽게 합니다.

이 프로젝트를 읽고 현재 검색 흐름을 설명해줘.

자치구 필터를 추가하려고 해.
아직 코드를 수정하지 말고,
수정할 파일과 구현 순서, 완료 기준을 제안해줘.

서울 API 키는 서버에서만 사용해야 해.
새 패키지는 필요한 경우에만 제안해줘.
계획에서 확인할 것: 화면의 선택값 → 서버 요청 → 검색 필터 → 결과 표시가 연결되어 있는가?
강사 메모
지역 필터를 제거한 시연용 사본에서 실행합니다. AI 답변을 모두 읽지 말고 수정할 파일과 완료 기준만 짚으세요. 범위를 벗어나는 리팩터링을 제안하면 이번 작업에서 제외하도록 요청하세요.

03 · 07:00–14:00

기능 하나를, 검증 가능한 크기로 요청합니다.

계획대로 자치구 필터를 구현해줘.

완료 기준:
1. 기본값은 서울 전체다.
2. 종로구를 선택하면 종로구 행사만 나온다.
3. 무료 행사 조건과 함께 사용할 수 있다.
4. 결과가 없으면 빈 결과 안내를 보여준다.
5. 기존 키워드 검색은 유지된다.

구현 후 관련 테스트를 실행하고,
내가 브라우저에서 확인할 순서를 알려줘.

한 요청에 로그인·지도·즐겨찾기까지 추가하지 않습니다. 지금은 지역 필터 하나의 완성에 집중합니다.

강사 메모
생성을 기다리는 동안 다음 구조 슬라이드를 설명합니다. 예상보다 오래 걸리면 기능 추가 범위를 줄이고 완성본으로 검증 단계를 이어가세요.

확인할 동작직접 입력통과 기준
지역 검색전시 + 종로구모든 결과의 지역이 종로구
조건 조합무료 행사만 체크무료 분류의 행사만 표시

자동 확인

npm test

조건 조합과 결과 없음처럼 쉽게 놓치는 동작을 확인합니다.

사람이 확인

원문에 별도 입장료가 있는지, 날짜와 장소가 맞는지 확인합니다. “무료” 분류만으로 부대비용까지 무료라고 단정하지 않습니다.

강사 메모
원본 데이터에 무료 행사로 분류되어도 입장료가 별도인 경우가 있습니다. AI가 만든 화면뿐 아니라 원문도 확인한다는 좋은 사례입니다. 조건에 맞는 행사가 실제로 없으면 그것도 정상 결과입니다.

DEBUGGING · 문제가 발생하면

증상 대신, 예상과 실제를 전달하세요.

종로구를 선택했는데 다른 지역 행사가 보여.

예상: 모든 결과의 district가 종로구여야 한다.
실제: 다른 지역 결과가 섞여 나온다.

요청값과 서버 필터 흐름을 확인해서 원인을 찾아줘.
이 문제를 재현하는 테스트를 추가하고 수정해줘.
관련 없는 파일이나 기능은 변경하지 마.
실제 문제가 있을 때 사용하는 예시입니다. 오류가 없다면 테스트 결과와 변경 사항을 확인하고 다음 단계로 진행하세요.
강사 메모
터미널 오류를 전달할 때 키나 인증 URL을 제거하세요. “안 돼, 다시 해줘” 대신 재현 조건, 예상 결과, 실제 결과를 주면 AI가 원인을 좁힐 수 있습니다.

  3. 같은 검색 조건으로 결과 확인
  4. 원문 링크와 빈 결과 안내 확인

환경변수는 강의 전에 등록하세요. 배포 후 서울 API 신청서의 사용 URL도 실제 데모 주소로 맞춥니다.

“로컬에서 동작하는 것과 다른 사람이 쓸 수 있는 것은
별도의 완료 기준입니다.”
강사 메모
현재 프로젝트의 Vercel 배포는 아직 검증하지 않았습니다. 반드시 강의 전에 사전 배포하세요. 라이브 배포가 지연되면 사전 배포 URL로 동작을 보여주고 현재 배포 상태를 설명합니다.

OPTIONAL · AI 키 연결을 검증한 경우

검색한 근거 안에서 AI가 답하게 합니다.

관련 행사 검색→자료를 AI에 전달→답변·출처 대조

사전 준비

  • GEMINI_API_KEY 설정
  • 계정에서 사용 가능한 모델 지정
  • 서버 재시작 후 실제 답변 확인
  • 배포 환경에서도 동일하게 검증

반드시 구분할 상태

  • 키 없음: 검색 결과만 제공
  • 자료 없음: 찾지 못했다고 안내
  • AI 실패: 검색 근거 유지
  • AI 성공: 답변과 원문을 대조
현재 실제 검증은 공공데이터 검색까지입니다. AI 생성은 키를 설정한 뒤 별도로 확인해야 합니다. 출처 번호 검증이 모든 문장의 사실성을 보장하지는 않습니다.
강사 메모
키 연결을 준비하지 못했다면 이 슬라이드는 설명만 하거나 건너뛰세요. AI 코딩으로 앱을 만드는 것과 앱 안에 AI 기능을 넣는 것은 다른 단계임을 알려주세요.

BACKUP · 흐름이 끊겼을 때

복구도 개발 과정의 일부입니다.

상황강의에서 이어갈 방법
코드 생성이 길어짐구조와 완료 기준 설명 → 보관한 완성본으로 검증
서울 API 연결 실패오류 안내 확인 → 사전 녹화 영상으로 정상 흐름 설명
조건에 맞는 결과 없음서울 전체로 범위 확대, 검색어를 전시·클래식으로 변경
AI 키·할당량 문제검색 모드로 시연, 생성 답변은 별도 연결 단계라고 설명
배포가 늦어짐사전 배포 URL로 검증, 현재 변경은 배포 중이라고 설명
녹화·완성본으로 전환할 때는 명확하게 말하세요. 현재 동작과 준비해 둔 결과를 구분하는 것도 검증의 일부입니다.
강사 메모
API 장애를 만나도 재시도를 반복하며 시간을 모두 쓰지 마세요. 진단에 1~2분을 쓰고 전환하세요. 코드 오류나 키 문제를 숨기기 위해 가짜 데이터를 실제 데이터처럼 제시하지 않습니다.
